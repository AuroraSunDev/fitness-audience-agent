# 作业三｜每日经营巡检 Skill 设计说明

## 1. 目标、边界与用户任务

面向单家虚构健身用品店铺的店长，回答「昨天最值得处理哪件事、依据是什么、处理后观察到什么」。产品是现有商策的一个只读 Skill，不是第二个平台。2026-11 数据和所有执行状态均为**教学 Mock**；没有真实京东数据、云调度、通知、预算写入、Hermes 服务或自主学习。

统一入口保留作业二 S1–S8。S8 的旧单指标巡检不再独立启用，而是连接到扩展后的「每日经营巡检」配置。旧键 `merchant-diagnosis-skill-v1` 不删除；若发现旧配置，新 Skill 默认 `saved:false, enabled:false`，要求重新确认四维监控范围。

## 2. Skill 契约与调度网关模拟

`daily-business-pulse@1.0.0`，店铺 `demo-fitness-001`，只读，时区 `Asia/Shanghai`。可编辑名称（≤36 字）、维度（流量/用户/交易/排名，至少一项）、每日或每周六、08/09/10 点、通知策略；店铺和只读权限不可改。保存后可启用，修改后保存/启用状态立即失效。

固定模拟时钟 `2026-11-15 09:00` 对应 11-14 日报；其他日期只可手动模拟。模拟步骤：校验配置与权限 → 数据就绪 → 查询选中维度 → 确定性规则 → 证据 → 报告 → 本机日志 → 模拟通知。运行状态为待模拟、执行中、完成/部分报告/失败/中断。Trace 展示步骤、模拟耗时、口径版本和失败码。关闭浏览器即停止，没有后台唤醒。

幂等键为 `shopId/reportDate/skillVersion/configHash`。相同键默认复用本机结果，不重复提醒；「显式重跑」覆盖该键的本机快照，保留重新执行的结果，但不二次模拟通知。没有实际消息渠道。

## 3. 报告、证据与错误恢复

日报显示店铺、数据日期、模拟执行时点、覆盖度和“预载/已模拟执行”区别；四维 KPI 均可点击。规则只使用可比基线：11-14 店铺 UV 缺口 1,000 / 预期 7,000 = 14.29%；付费缺口 500 / 自身预期 1,300 = 38.46%；付费占**总缺口** 500 / 1,000 = 50%。相关缺口不相加，也不称为因果。用户与交易无同口径基线时只展示观察值。排名同设备、地域、时间条件从第 6 到第 12 名，只作为待核验线索。

证据卡含指标 ID、版本、定义、分子分母、时间窗、来源、血缘、模拟取数时间、质量状态。缺维度给部分报告；UV 口径 v1.0/v0.9 冲突时暂停流量结论；排名采样条件不一致则取消排名告警；超时/中断保留 Trace、不生成完整日报；越权拒绝并写 Mock 审计。只有 11-14 的流量报告可带告警 ID 进入原作业二 S2；其他日期提示不支持，不借用旧数据。

## 4. 本地记忆与受控治理

浏览器仅保存单店 Skill、运行快照、事故关联、反馈和审计，不保存真实商家敏感数据。记录带 `shopId/createdAt/updatedAt/source/version`；“不适用”反馈设置 7 天 `expiresAt`，只压制同一事故的重复建议，告警证据仍可查看；若新缺口较被否决时扩大超过 25%，再次提醒。待办支持待处理、已处理、暂缓、不适用及备注/模拟时间。11-15/16 关联 `INC-UV-GAP` 的变化只写观察，不宣称处理动作导致恢复。清除作业三本机演示数据需二次确认，原作业二键保留。

治理页为**手动触发 Mock**：反馈 → 合法的话术/排序/FAQ 待审提案 → 影子比较 → 人工批准或拒绝 → 演示版本记录 → 人工回滚。未经影子比较和人审不能发布。指标口径、阈值、权限、资金动作、评测标准均不允许自动修改。演示版本号不代表线上 Skill 已部署。

## 5. 验证与待验证假设

在 390×844、375×844 与桌面 1280×844 浏览器完成主链路和失败态点击，检查横向溢出与控制台。自动测试覆盖固定数据守恒、规则、迁移、幂等、反馈 TTL、治理和原 S1–S8 数据/状态机。三条实际问题与处理见 [走查记录](走查记录.md)。

「店长更偏好有优先级、证据和行动闭环的日报」仍是业务假设，尚无真实商家访谈、采纳率或经营增量验证；Demo 点击不等于真实业务 KPI。
