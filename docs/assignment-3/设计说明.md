# 作业三｜每日经营巡检 Skill 设计说明

> 2026-10-24 商家体验修订：本说明记录内部实现边界；商家界面直接展示日报，不展示教学、Mock、Skill、技术契约或测试场景。以下交互说明按修订后的产品执行。

## 1. 目标、边界与用户任务

面向单家虚构健身用品店铺的店长，回答「昨天最值得处理哪件事、依据是什么、处理后观察到什么」。产品是现有商策的一个只读 Skill，不是第二个平台。2026-11 数据和所有执行状态均为**教学 Mock**；没有真实京东数据、云调度、通知、预算写入、Hermes 服务或自主学习。

统一入口保留 S1–S8。S8 连接同一项每日巡检设置。用户进入巡检即看到门店日报；默认四维、每日 09:00，无需先创建或命名 Skill。设置页提供一项「开启每日经营巡检」动作，在内部完成配置保存和启用。旧存储键保留，范围扩展后不静默开启提醒。

## 2. Skill 契约与调度网关模拟

内部契约为 `daily-business-pulse@1.0.0`，店铺 `demo-fitness-001`，只读，时区 `Asia/Shanghai`。商家只编辑监控维度、频率、巡检时间、提醒方式；名称、版本、店铺 ID、时区等内部字段不出现在设置表单。提交设置前保持原设置有效，提交时一次校验并保存启用；空范围不覆盖旧设置。

底层仍使用固定数据与模拟状态机，关闭浏览器没有后台唤醒。商家点击「更新日报」时只看到更新数据、核对变化、整理日报的进度，可取消；内部 Trace、运行键、耗时和失败码不放在商家旅程里。

内部幂等键为 `shopId/reportDate/skillVersion/configHash`。更新相同报告时覆盖该键快照，不二次模拟通知；商家无需理解去重键或显式重跑。没有实际消息渠道。

## 3. 报告、证据与错误恢复

日报显示店铺、数据日、更新时间、重点动作、四维 KPI 和重要异常。技术状态不进入首屏；数据不足以判断时仍需在相关指标/详情处说明。指标与异常点击进入独立详情页，返回恢复日期和阅读位置；根页返回经营诊断。历史页只呈现日期、经营表现和查看入口。11-14 的 1,000 总缺口、500 付费缺口、38.46% 自身降幅与 50% 结构贡献保持不变，不相加也不写成因果。

证据卡含指标 ID、版本、定义、分子分母、时间窗、来源、血缘、模拟取数时间、质量状态。缺维度给部分报告；UV 口径 v1.0/v0.9 冲突时暂停流量结论；排名采样条件不一致则取消排名告警；超时/中断保留 Trace、不生成完整日报；越权拒绝并写 Mock 审计。只有 11-14 的流量报告可带告警 ID 进入原作业二 S2；其他日期提示不支持，不借用旧数据。

## 4. 本地记忆与受控治理

浏览器仅保存单店 Skill、运行快照、事故关联、反馈和审计，不保存真实商家敏感数据。记录带 `shopId/createdAt/updatedAt/source/version`；“不适用”反馈设置 7 天 `expiresAt`，只压制同一事故的重复建议，告警证据仍可查看；若新缺口较被否决时扩大超过 25%，再次提醒。待办支持待处理、已处理、暂缓、不适用及备注。11-15/16 关联问题的变化只写观察，不宣称处理动作导致恢复。底层保留定向清除方法及其测试，商家页面不放演示数据清除入口，原作业二键保留。

治理不再出现在商家导航。内部提案、影子比较、人审、版本与回滚逻辑及单测保留，用于实施验证；不把这些工程概念展示给店长。没有真实自动学习或部署。

## 5. 验证与待验证假设

在 390×844、375×844 与桌面 1280×844 浏览器完成主链路和失败态点击，检查横向溢出与控制台。自动测试覆盖固定数据守恒、规则、迁移、幂等、反馈 TTL、治理和原 S1–S8 数据/状态机。三条实际问题与处理见 [走查记录](走查记录.md)。

「店长更偏好有优先级、证据和行动闭环的日报」仍是业务假设，尚无真实商家访谈、采纳率或经营增量验证；Demo 点击不等于真实业务 KPI。
