# 每日经营巡检｜设计说明

## 产品位置与用户链路

每日巡检与经营诊断位于同一商策工作台，是两个平级入口。经营诊断回答一次性问题；每日巡检按订阅规则检查昨日经营数据，交付可处理的日报，再支持下钻与继续诊断。配置是辅助页。

主链路：开启巡检 → 日报 → 异常与证据 → 处理或继续诊断 → 次日跟进。

全店默认巡检覆盖流量、用户、交易、搜索排名四维；S8 保存的诊断专项关注只保留原问题、口径、基线、证据和流量范围，不自动开启或扩大全店巡检。

## 技能层与工具集

内部执行单元为 `daily-business-pulse@1.0.0`，只读、单店、北京时间。取数按域拆分，不设万能分析接口：

| 工具 | 输入 | 输出 | 失败处理 |
| --- | --- | --- | --- |
| `queryTraffic` | `{date}` 与店铺授权上下文 | 店铺访客、参考值、互斥渠道、质量状态 | 缺流量时保留其他三域 |
| `queryCustomers` | 同上 | 新访客、回访访客、质量状态 | 缺数不补零，不借用别日 |
| `queryTransactions` | 同上 | GMV、买家、订单、客单、访客分母状态 | 分母缺失或冲突时暂停转化率 |
| `queryRanking` | 同上 | 前后名次、采样条件、质量状态 | 不可比时不生成变化告警 |
| `getEvidence` | `{date,metricId}` 与授权上下文 | ID、版本、定义、时间、来源、血缘 | 未授权或未知指标拒绝 |
| `recordActionFeedback` | 事项、状态、备注、缺口 | 带生效日和修订序号的处理记录 | 仅允许四种状态 |

工具拒绝自由文本和额外字段；编排只读取所选维度。交易转化率依赖同口径访客分母，不能把缺失算作零。

## 调度、上下文、停止与恢复

一次执行依次校验配置及权限、检查数据就绪、四域独立取数、应用确定性规则、附加证据、生成日报、记录执行和送达。任务输入限于本店授权范围、报告日期、订阅维度及版本。此前诊断只带来源 ID、问题、证据和受支持的日期，不跨店复用用户明细。

无权限、配置无效或关键查询超时停止成功结论；单域缺数生成部分日报，取消运行保留已有日报。报告以 `shopId/date/version/configHash` 去重；提醒按报告键、渠道和日期单独去重。先手动生成、后开启订阅时仍可首次送达。

## 证据、记忆与处理闭环

日报展示数据日、00:00–24:00 时间窗、授权范围、覆盖度、更新时间、四维 KPI、优先事项和次日跟进。证据卡可展开指标 ID、口径版本、分子分母、来源、血缘及取数时间。付费渠道缺口只是总缺口的一部分，不能写成已证实原因。

“已处理”只表示店长记录动作；“恢复”必须看后续经营数据。反馈保留业务生效日和修订序号。回看旧日报可以补录旧状态，不会覆盖新日期的状态。进入经营诊断时保存报告、日期、异常、指标、证据及原页面路径；返回恢复原日期、异常与滚动位置。历史报告和导出优先读取已保存快照，不按新规则重算旧版本。

## 受控治理与实现边界

规则维护在独立入口。商家反馈可提出话术或排序候选，三日历史对照和人工批准后发布新版本，可回滚。指标定义、阈值、数据权限、评测标准和资金动作不能自动修改。

目前是固定单店数据与浏览器状态原型，尚未接入真实经营数据、后台定时任务、外部通知和资金接口。这一实现说明只在交付文档中。71 项 Node 测试通过；390、375、1280px 浏览器主链路及失败态点击通过，控制台 0 错误。截图见 [screenshots-v2](screenshots-v2/)，走查见 [走查记录](走查记录.md)。
