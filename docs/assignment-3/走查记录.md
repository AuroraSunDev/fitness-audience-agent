# 作业三走查记录

2026-10-24。原型在本地预览，以 390×844、375×844、1280×844 实际浏览器点击；截图见 [screenshots](screenshots/)。下列问题来自实际运行与测试红灯，并非虚构商家反馈。

| 发现 | 影响 | 处理与复测 |
| --- | --- | --- |
| 排名采样改为不同设备/地域时，初版报告仍显示“完整 4/4”。 | 商家可能把不可比快照误当成可信排名趋势。 | 把排名不可比计入部分覆盖，取消排名告警；规则测试先失败、修复后通过，并在浏览器保存了“排名不可比”截图。 |
| 本机完成巡检后再把建议标记“不适用”，初版历史快照仍显示原待办。 | 7 天重复建议抑制没有反映到已存日报，反馈闭环失效。 | 在展示持久快照时依据最新反馈重算待办可见性；告警证据保留。持久快照测试先失败、修复后通过，浏览器验证反馈刷新后保留。 |
| 选择“模拟超时/无权限”后，初版的“查看预载日报”仍可显示正常完整四维报告。 | 失败态可能被误读为成功。 | 对两种场景显示“无可用日报”并引导查看 Trace；单测先失败、修复后通过，浏览器走通超时和越权审计。 |
| 从 11-16 历史返回总览，选中日期会保留；测试脚本最初直接找 11-14 的“显式重跑”未找到。 | 若不注意当前日期，可能误以为重跑入口丢失。 | 走查脚本显式切回 11-14；页面保留日期选择和运行键提示。未发现产品数据错配。 |
| 固定模拟时钟 11-15 09:00 原可对选中的未来 11-15 日期执行“到点巡检”。 | 违反时间就绪边界。 | 限定“到点执行”只对应 11-14 与每日 09:00 配置；其他日期可手动模拟。测试先失败、修复后通过。 |
| 已有四维运行后修改 Skill 仅选流量，初版仍把旧四维快照标为当前“已执行”报告。 | 配置版本与报告范围不一致。 | 按完整 run key 关联当前报告；旧快照仍在历史日志，但当前视图回到仅流量的预载数据。测试先失败、修复后通过。 |
| 治理批准后的版本列表初版仍显示 `1.0.0`，以及新建诊断会误带上一个告警 ID。 | 版本审计和来源追溯误导。 | 保留发布记录的真实演示版本；新建议问法清除旧告警上下文。单测/浏览器检查均先失败、修复后通过。 |

浏览器走查完成的链路：统一入口 → 保存/启用 Skill → 分步模拟执行 → 四维日报 → 证据 → 待办反馈 → 刷新后恢复 → 次日历史复盘 → 治理提案/影子比较/人工批准/回滚；另验证缺数、排名不可比、口径冲突、重复去重、超时、越权与二次清除。三个视口无水平溢出，浏览器控制台无阻断错误。作业二 S1→S2→S3→S4→S5→S8 桥接仍可点击；S6/S7 的旧自动测试保留。
