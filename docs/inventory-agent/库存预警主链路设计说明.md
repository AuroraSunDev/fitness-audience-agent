# 库存预警 Agent｜主链路设计说明

**版本** v1.0 · **使用者** 品牌负责人、库存计划员 · **目标** 让异常从发现到审批有据可查、有人负责。

## 业务流程

| 页面 | 用户要完成的事 |
|---|---|
| S1 库存总览 | 按品牌、店铺、仓库查看健康度、预警数和相关库存资金占用。 |
| S2 预警列表 | 按影响金额排序，筛选 P0/P1/P2，批量指派或带原因标记误报。 |
| S3 SKU 详情 | 核对库存曲线、分仓、在途、活动和预计到货时间。 |
| S4 证据卡 | 展开并复制指标 ID、口径版本、时间窗、数据源、血缘、取数时间。 |
| S5 归因分析 | 查看主因、贡献度及对应证据。 |
| S6 处置建议 | 比较动作、数量、影响预估、成本、时效和失效条件。 |
| S7 确认与审批 | 预览影响、二次确认，生成审批单号后跟踪或撤销。 |
| S8 异常状态 | 处理延迟、无数据、取数失败、超时和低置信度。 |

对话入口回答当前范围的库存风险、原因、建议和审批状态，并引导到相应页面。切换品牌、店铺、仓库或 SKU 时重新确定分析对象，不沿用上一对象的结论。

## 判定与示例

缺货风险按 **可售库存 ≤ 近 30 天日均销量 × 补货周期 × 安全系数** 判断；活动期修正销量，并核对在途、锁定及商品状态。积压、周转使用独立规则。可售口径 v1.2 为 **实物 − 锁定 − 残次 + 已达可售条件的在途**；普通在途单列。P0 为在投广告等关键 SKU 断货，P1 为常规断货或显著积压，P2 为长尾轻微异常；单店每天最多即时推送 3 条 P0，同 SKU 同异常 72 小时内不重复推送。

主案例使用 **2026-11-15 09:00** 快照：A 店 `YM-2048` 实物 190、锁定 20、残次 2，可售 **168 件**；日销 24 件、交期 9 天、安全系数 1.2，安全库存 **259.2 件**，现货覆盖 **7 天**。供应商预计 11 天后到货，到货前预计缺口 **96 件**。建议 B 仓调拨 **120 件**，2 天到达、费用 **¥480**；B 仓从 340 件降至 220 件，按日销 10 件仍覆盖 22 天。按每件贡献毛利 ¥45 估算，可规避毛利损失 ¥4,320，扣除调拨费后净影响约 **¥3,840**。

## 边界与停机规则

系统只在已授权范围内读取并分析数据。建议为待确认方案；跨店调拨由品牌负责人审批，审批单号是写操作前提。审批通过、执行回写和效果验证是不同状态，只有效果核验后才标记“已解决”。误报须记录原因并进入治理。

每轮分析保留角色与授权范围、当前筛选、SKU、时间窗、口径版本、相关证据及审批状态。缺关键证据、时点不一致、权限不足、建议失效或低置信度时停止生成可审批动作。快照延迟超过 6 小时标明时点并按 T-1 判断；无结果显示“无数据”而非 0；取数失败重试一次后转人工；超过 90 秒返回阶段结果；证据冲突时说明不确定部分并支持人工复核。

本版使用固定情景数据和本地审批状态，供产品、设计与研发核对主链路；不接入实际库存、采购或审批系统。
