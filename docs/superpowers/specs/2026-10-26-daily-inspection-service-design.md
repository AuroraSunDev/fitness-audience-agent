# 每日经营巡检：日报与处理闭环

依据 2026-10-26 用户确认的产品方案。本版覆盖旧任务书中“扩展 S8 即完整巡检”“商家页面展示教学 Mock”“先配置再手动执行”的交互要求；旧数据锚点继续有效。

- 同平台、单店、只读。经营诊断与每日巡检是两个工作入口；main 保持作业二，所有改动只在 `feat/daily-business-pulse`。
- 店铺订阅采用预置四维方案，一次开启，后续看日报；设置是辅助。S8 仅保存本次诊断与专项关注，不能自动开启四维订阅。
- 日报先展示范围与完整性、今日重点、四维指标、优先事项、上次问题跟进；可下钻证据、继续诊断、记录处理、查看历史。
- 11-14 / 15 / 16 三日各有独立四维数据；保留 11-14 UV 6000、预期 7000、付费缺口 500 等锚点。日期切换必须换数；历史结果有快照。
- 流量、用户、交易、排名分别由窄工具读取；输入受限，权限由调用上下文控制，返回结构化状态与证据。禁止万能分析工具。
- 商家处理状态与数据恢复状态独立。次日优先展示旧问题；重复提醒按事项去重，恶化重新提醒。反馈有时间，不可泄漏到更早的历史报告。
- 持续关注保存来源诊断、问题、口径、相对取数规则与证据；历史报告保存实际日期。调度与消息状态分开，部分数据就绪生成部分报告。
- 反馈可形成排序/话术改进提案；历史样本对照后人工批准才发布，能回滚。指标、阈值、权限和预算不在自动学习范围。
- 治理使用独立维护入口，不进入商家导航。实现边界只在技术说明中说明，不混入商家界面。
- 交付包括更新方案、工具契约、可点击报告、可独立打开的 HTML、三日案例、失败与治理案例、截图和走查记录。
- 当前是固定数据与浏览器状态原型；不创建真实商家定时任务，不发送外部通知，不连接资金接口。

验收：首次开启与暂停/恢复；专项关注不扩大范围；日报→异常→证据→诊断→返回；处理→次日跟进→刷新；部分数据、口径冲突、排名不可比；提案→对照→审核→版本→回滚；独立 HTML 离线交互；375/390/1280px 与原诊断回归。
