# 作业二：大促后流量诊断原型设计

## 目标与边界

面向动燃健身旗舰店的中小商家店长，在商智 App 手机端回答“11.11 后第 3 天流量掉了，是正常回落还是有问题”。本次只实现这一项教学演示任务；数据、工具、审批、巡检均为本地模拟，不连接京东、广告或客服服务。作业一的跨品类人群机会立项方向保持独立，不能把本次预算审批示范写成其 MVP 的生产能力。

## 采用方案与取舍

沿用仓库的原生 HTML/CSS/JavaScript 与商策红色视觉，替换旧单屏展示页为一个 390px 优先的可点击八状态任务流。备选方案是保留旧页面并新增第二套诊断系统，或引入 React；前者违背单场景约束，后者增加静态 Pages 的构建负担。以单一 fixture、纯函数计算和有限状态转移为界，避免把演示数据散落在 UI。

## 状态和主要行为

S1 入口（店铺与三条数据相关问法）→ S2 只读查询计划（可编辑受支持条件）→ S3 四步执行（阶段发现、中断/恢复）→ S4 有证据的结论与三项排序动作。S4 可打开 S5 证据卡与双口径比较；缺数、冲突、超时或无数据的另一口径转入 S6，展示已知/未知、换口径与模拟人工接管。S4 的广告建议可进入 S7，必须先二次确认，再生成模拟审批单；审批状态与真实执行严格分离。S4 可进入 S8，保存/调整/关闭仅在本机生效的巡检技能配置。

## 数据与可信约束

正常 fixture：峰值 UV 10,000，11.14 实际 6,000，预期 7,000；渠道互斥可加总。下降 4,000 中，预期回落 3,000、额外缺口 1,000，75%/25% 是下降量分解而非置信度。渠道额外缺口 500/250/200/50 只用于优先排查，不推断广告预算导致损失。所有卡片、图表与结论由同一计算结果渲染。口径比较展示定义差异；不支持的口径不沿用 SHOP_UV_001 数值。页面固定标注“教学演示·Mock 数据”。

## Harness 与验证

工具层提供确定性只读查询/对比/下钻/归因/证据与模拟建议；上下文保留店铺、计划、指标 ID/版本、已取得证据和任务步骤，不把无关旧对话带入。停止于完整结论、用户中断、证据不足、口径冲突或超时；不能在失败后显示完整成功结论。写操作只能形成模拟申请，二次确认与审批前绝不进入执行态。Trace 在本地展示会话→任务→步骤→工具状态。用 Node 内置测试检查计算、数据一致性、受限条件、状态与审批，再以真实浏览器走通 S1–S8 并从运行页面截取八屏。
