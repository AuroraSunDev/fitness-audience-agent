DATA AGENT · ASSIGNMENT 02 · PRODUCT DESIGN NOTE

经营诊断对话主链路

中小商家店长 · 2026-11-14（11.11 后第 3 天）· 商智 App 为主，PC 辅助 · 固定问题：「大促后流量掉了，是正常回落还是有问题？」

设计目标：在单次诊断里让店长先确认查什么，再看阶段过程、可追溯结论与有边界的下一步。示例结论为下降 4,000 人中 75% 属于参考预期回落、25% 为额外缺口；渠道贡献不是因果归因。所有数值与外部动作均为 Mock。

上下文取舍与证据

保留当前店铺与日期、原问题、指标 ID／版本、对比基线、下钻维度、已完成工具步骤、证据 ID、人工接管原因。
不保留无关历史对话、未授权店铺、个人级用户数据；不把上一口径的数值搬到新口径。
证据卡明确展示指标 ID、口径版本、时间窗、来源、血缘、取数时间；店铺 UV 与商品详情页 UV 并排比较，后者缺少日值时不冒用 6,000。

停止条件与护栏

  • 计划条件超出演示数据、数据缺失、指标版本冲突、步骤超时 → 停止最终归因；保留已知部分，明确未知，不生成貌似完整的贡献排序。
  • 用户可中断，恢复沿原任务进度；只读诊断不会改预算。高影响动作要求二次确认与审批，未获批准不执行。

失败态与产品衡量

  • S6 给出「改口径／改计划」和「转人工」两个出口；接管不是自动修复，超时可重试，冲突需数据负责人确定权威版本。
  • 可追溯性：结论能回到证据卡与 Trace；人工介入率：低置信度场景是否被正确引导至接管，不能把本地模拟值当作线上 KPI。
演示边界：11.14 店铺 UV 6,000、参考预期 7,000；付费广告缺口 500、自然 250、老客 200、活动 50。基线为课程示例，不是真实预测。Skill 仅写入本机浏览器；无后台巡检、通知或真实审批。
