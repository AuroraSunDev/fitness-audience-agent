大促后流量诊断

中小商家店长 · 11.11 后第 3 天（2026-11-14）· 手机为主，PC 辅助
用户问题：「大促后流量掉了，是正常回落还是有问题？」

核心任务：先确认分析范围，再分清正常回落与额外缺口，核对依据并选择行动。访客较峰值减少 4,000，其中参考预期回落 3,000、额外缺口 1,000；付费渠道贡献额外缺口的 50%，优先核查计划与曝光。结构贡献不直接等于原因。

完整用户链路

S1 开始提问3 条结合当前店铺数据的问法
S2 确认计划指标、时间窗、对比期、维度可核对和修改
S3 分析进展取数、下钻、贡献计算；阶段发现与中断恢复
S4 诊断结果一句话结论、贡献排序、三条影响/成本建议
S5 核对依据证据六要素、两种指标口径比较
S6 进一步复核具体未知、调整口径或转人工、复核单号
S7 预算申请影响、二次确认、审批单与取消路径
S8 保存与复用保存本次分析与口径，订阅后续流量巡检

工具层与执行权限

查询工具get_metric_def、query_metric、drill_dimension、run_attribution、get_evidence_card、propose_action；诊断按只读方式逐步执行。
动作边界预算申请 ¥300/天 → ¥350/天，持续 2 天，新增额度上限 ¥100；二次确认后进入待审批。额度增加不等于实际消耗或必然带来流量。
状态留痕诊断唯一 ID、问题、查询计划、工具步骤、状态与证据关联；人工复核携带上下文，反复点击不重复计算介入次数。

上下文与证据

保留店铺、原问题、数据日、指标及版本、参考基线、渠道维度、已完成步骤、已知/未知部分、证据与复核原因。
舍弃无关历史对话、其他店铺数据、个人级用户信息；切换指标后重新取数，不搬用上一口径的值。
证据卡指标 ID、口径版本、时间窗、来源、血缘、取数时间；店铺 UV 与商品详情页 UV 比较统计范围。缺少详情页日值时不冒用店铺 6,000 人。

停止条件与错误恢复

数据缺失、指标版本冲突、查询超时或范围无可用数据时，停止最终结论与贡献排序，保留已完成部分，并明确缺什么。

用户中断后可从原步骤继续；低置信度提供「调整统计口径」和「转人工复核」。复核显示单号、待处理状态与需核对事项；超时可重试。

保存与后续跟进

保存当前诊断结论、原问题、数据口径、参考基线、渠道维度和证据；在入口可重新打开原结果，无需再次执行。

流量巡检按相同口径检查「低于参考预期 10% 且缺口至少 200 人」；支持频率、时间、下次巡检、暂停和恢复。该订阅卡属于本次诊断的延续。

产品衡量口径

结论可追溯率：具备完整六要素证据的已完成诊断数 ÷ 已完成诊断数。

人工介入率：用户主动转交人工的诊断数 ÷ 发起的有效诊断数；按诊断 ID 去重。证据不足本身不计作已发生人工介入。
