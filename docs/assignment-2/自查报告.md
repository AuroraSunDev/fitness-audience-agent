# 经营诊断主链路自查

核查日期：2026-10-26。核查对象为仓库 main 和现有 GitHub Pages，并与修订代码逐项对照。下述结论是产品自查，不代替教师评分。

## 核查结论

修订前的 main 八个界面都存在，并可按链接走通；主要不足在于界面混入教学/Mock/技术说明、人工出口仅停在资料包、保存复用和 KPI 留痕不够完整。不能仅因八屏齐全就称整个交付完全合格。

修订在 main 独立实施，只包含经营诊断及其 S8 流量巡检订阅卡。每日巡检平台、radar 模块、独立日报导航没有合并进 main。

| 状态 | 验收要求 | 本次实际验证 | 结果 |

## 按评分维度检查

- 链路完整性（25）：八状态均实际点击，主路径与分支有返回/恢复；不是只放八张静态图。
- 证据与可信度（25）：结论关联六要素；口径切换不搬数；缺失口径不生成完整结论；数据守恒和分母有自动测试。
- 受控执行（20）：只读诊断与预算申请分开；额度影响、二次确认、单号和取消路径均已核对。
- 失败态设计（15）：缺数、冲突、超时与范围不支持有状态机测试；用户路径能进入证据不足并完成口径调整或人工复核。
- 设计说明（15）：重新生成一页 PDF，覆盖工具集、上下文取舍、停止条件、失败恢复和 KPI 定义；截图和走查记录同步更新。

不把测试中的点击次数当作真实商家人工介入率，也不把固定数据原型说成已接入京东、广告审批或后台定时服务。实现状态记录在仓库文档，商家页面保持正常产品用语。
