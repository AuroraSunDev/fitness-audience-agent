## 3. Phase 1：数据契约与四维规则引擎（先做）

### 3.1 保留作业二事实锚点

`SHOP_UV_001@v1.0`：店铺日去重访客 UV，四类**互斥主渠道**（付费、活动、自然、老客来源）可加总为店铺 UV，时区 `Asia/Shanghai`。

必须保留以下数值：

```text
2026-11-11 peak UV = 10000
2026-11-14 actual UV = 6000
2026-11-14 expected UV = 7000
2026-11-14 channel actual = paid 800 + campaign 2050 + organic 2050 + returning_source 1100
2026-11-14 channel expected = paid 1300 + campaign 2100 + organic 2300 + returning_source 1300
expected gap = 1000
paid channel gap = 500
```

这些数据来源于现有课程 Mock，不是公共京东经营数据。

### 3.2 新增多日模拟时间序列

按产品方案定义 11-11 至 11-17 的 UV/expected（11-14 锚点必须不变），至少为 11-14、11-15、11-16 提供可打开的报告。

如增加渠道数据，要完整满足按主来源口径求和；未提供的细节必须在 UI 标为未覆盖。时间序列由固定 fixture 决定，不使用完全随机数据，以便回归测试和可复现截图。

### 3.3 四维报告数据

- 流量：总 UV、主来源渠道 UV、参考预期与额外缺口。
- 用户：11-14 新访客 4,200、回访访客 1,800，`4,200+1,800=6,000`；**不要将「回访访客」与主来源 `returning_source 1,100` 混为一谈**。
- 交易：11-14 支付买家 180、支付订单 180、支付 GMV ¥33,300、订单客单价 ¥185；买家转化率 `180/6000=3.0%`；明确模拟设定每位买家一单。
- 排名：关键词「普拉提弹力带」可比快照第 6→12 名，采集条件与时间戳一致才能比较；排名降低不意味着已经证明访客下降的原因。

请为每个 metric 提供数据字典：`metricId`, `version`, `unit`, `definition`, `numerator`, `denominator`（必要时）, `timeWindow`, `source`, `lineage`, `fetchedAt`, `qualityStatus`。

### 3.4 纯函数异常规则

默认规则（可内置配置，UI 只开放必要项）：

1. 总 UV 缺口：相对预期下降至少 10% 且绝对缺口至少 200；11-14 命中。
2. 付费渠道：相对预期下降至少 15% 且绝对缺口至少 200；11-14 命中。
3. 关键词排名：相同采集口径、条件和可比时点下下降至少 5 位，标为**待核验**；数据不可比则不报警。
4. 交易/人群缺少足够可比基线时展示观察值，不得凭空给「严重异常」。

让计算决定展示，禁止硬编码 `-14.3%` / `50%` 作为独立的 UI 真值。`500/1300=38.46%`；`1000/7000=14.2857%`；基线与分母必须在证据卡中展示。

### 3.5 告警合并与幂等

- 同一问题跨日关联 `incidentId`，实例可有不同 `alertInstanceId`。
- 不能将店铺总 UV 缺口和付费渠道缺口相加成新的损失值。
- 相同 `shopId + reportDate + skillVersion + configHash` 的重复巡检请求应复用已有结果或展示为显式重跑；不能重复发模拟通知。
- 把待办、处理状态与告警实例分开建模。

**Phase 1 完成标准**：新纯函数与数据字典单测通过，作业二 `node --test tests/*.test.mjs` 仍通过。

## 4. Phase 2：Skill 卡、Mock Scheduler 与执行状态

### 4.2 兼容并迁移原 S8

现有 `merchant-diagnosis-skill-v1` 仅是单指标「大促后流量异常巡检」。扩展范围后，**不能自动继承已启用状态**；需要用户确认新增监控维度。建议迁移后配置默认为 `enabled:false`，新键如 `merchant-daily-radar-skill-v1`。保留旧键或安全备份，不无告知清除用户本地状态。确保作业二 S8 链路依然可以访问新 Skill 设置。

### 4.3 调度模拟

**没有真实后台**。提供明显标注「模拟到点执行」「手动模拟运行」的按钮，并模拟以下步骤：

`validate config → check data readiness → query 4 domains → evaluate anomalies → attach evidence → build report → record log → mock notify`。

时钟优先采用固定教学模拟日期（例如 `2026-11-15 09:00 Asia/Shanghai` 生成 `2026-11-14` 日报），不要依赖真实现在时间跳到未来。演示频率、下次执行时间必须从模拟时钟和配置计算，并明示「关闭浏览器不会继续运行」。

运行状态：`idle → scheduled_mock → running → completed | partial | failed | interrupted`。允许手动重跑，同一配置需要清楚显示幂等行为；运行日志有步骤、模拟耗时、失败码、指标口径版本。

**Phase 2 完成标准**：Skill 配置、启停、重存、迁移、模拟执行/失败/重复运行均可独立测试。

## 5. Phase 3：HTML 交互报告（评分核心）

### 5.1 首页

顶部显示：店铺、日报数据日期、模拟执行时间、数据完整度、演示标签。

核心摘要示例（只能由数据计算后生成）：

> 11-14 店铺 UV 比参考预期少 1,000（-14.3%），付费渠道缺口 500、贡献总缺口的 50%；大促正常回落和额外缺口需要区分。优先检查广告计划运行状态，尚不能断言因果。

### 5.2 四维指标卡

流量、用户、交易、排名必须都可点入详情。信息包含日期、口径、对比基线、样本完整性、数据来源；不存在适用基线时应显示「暂无可比基线」，而不是生成一个随意红/绿箭头。

### 5.3 异常与证据

告警按可说明的优先级排序，卡片显示：标题、指标变化、阈值、影响面、状态、证据 ID、下一步建议。点击进入：趋势/渠道、证据卡六要素、口径说明、仍未确认的部分。

流量详情应能衔接作业二 S2（若日期受支持），并保留来源告警 ID 与返回报告的入口；不要重复开发独立的第二套诊断流程。

### 5.4 今日待办与后续复盘

- 每条待办可以 `待处理 / 已处理 / 暂缓 / 不适用`，允许填写备注与模拟完成时间。
- 下一日报告显示上一日有关联 `incidentId` 的变化、已处理状态和改善或恶化的**观察**。
- 明确提示「观察到流量恢复不等于证明处理动作造成恢复」。
- 对重复提醒做有限时抑制，但新的重大异常不能被旧反馈完全屏蔽。

### 5.5 历史

至少在 11-14、11-15、11-16 报告间切换；切换后 KPI、异常、证据和反馈按当日正确更新。刷新后本地保存的已处理记录仍存在，不能在历史页创造不曾运行过的真实后台任务；未模拟执行的日期可显示为「仅预载数据/可模拟运行」。

**Phase 3 完成标准**：手机和 PC 通过实际点击的成功路径；日期切换、异常详情、证据、继续诊断、待办、复盘全部有有效反馈。

## 6. Phase 4：失败态、记忆与受控自进化

### 6.1 必测失败状态

- 任一维度数据缺失 → 部分报告，未覆盖区显示不可判断；
- 指标定义/版本冲突 → 错误标识和待人工确认，不强行归因；
- 关键词排名采集条件不一致 → 不计算有效排名变化；
- 模拟超时或用户中断 → 保留阶段性结果与 Trace，不生成完整结论；
- 无权限 → 显示拒绝与模拟审计记录；
- 同一天/配置重复运行 → 明确去重/重跑，不生成重复通知。

### 6.2 记忆（浏览器本地）

保存 Skill 设置、执行历史、已处理/暂缓/不适用反馈、`incidentId` 状态、版本及模拟审计事件。每条持久记录至少有 `shopId`, `createdAt`, `updatedAt`, `source`, `version`；需过期的数据加 `expiresAt`。

例如「暂不适用建议」设置初始抑制期 7 天（用户可重置）；如出现超出旧事件范围的新重大异常，仍应提醒。提供「清除本机演示数据」入口并二次确认（不要清除作业二数据，除非用户明确同意）。

### 6.3 治理演示

提供简单的高级/教师治理视图（无需完整管理后台）：

`商家反馈重复提醒 → 系统生成优化话术/排序的待审提案 → 模拟影子回放比较 → 人工批准/拒绝 → 发布技能版本记录 → 可回滚`。

必须明示：这是手动触发的 **Mock 治理工作流**，不是运行中的自进化 AI。**严禁**自动改指标口径、权限、检测阈值、评测标准或资金动作。能够看出哪些改动合法、哪些被禁止即可。

**Phase 4 完成标准**：每个失败态有可进入的演示路径；历史记忆可持久、可查看、可清理；治理必须经过人工确认并有审计记录。
