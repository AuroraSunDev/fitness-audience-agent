# 商策｜商家经营工作台

同一商策平台内保留作业二「大促后流量诊断」S1–S8，并增量加入作业三「每日经营巡检」Skill。主端按 390px 手机宽度设计，375px 与桌面也可使用。所有数据、任务、审批、调度、通知和治理均为教学 Mock；2026 年 11 月是课程假设情景，不是已发生经营事实。

## 体验

本地打开页面后，用顶部「经营诊断 / 每日巡检」切换。进入每日巡检直接查看「动燃健身旗舰店 · 经营巡检日报」：今日重点 → 经营概况 → 优先关注 → 今日待办。点击指标或异常进入独立详情，口径与来源按需展开。

「开启巡检」进入巡检设置，默认关注流量、用户、交易、搜索排名，每天 09:00。商家可调整范围、频率、时间和提醒方式，点击「开启每日经营巡检」即可完成设置；已开启时可保存修改或暂停。底部导航为日报、今日待办、历史报告、巡检设置。顶部返回箭头逐级返回并保留日期与阅读位置；日报根页返回经营诊断。原 S8 也可进入同一设置页。

实现边界保留在仓库文档：运行逻辑使用固定 fixture 与浏览器状态，不包含云定时服务、真实通知、广告写入、京东 API 或 Hermes/LLM。技术契约、测试场景、治理与 Mock 说明不进入商家页面；规则和治理底层测试仍保留。

## 本地预览与检查

无需安装依赖。在仓库目录运行 `python3 -m http.server 4173`，然后打开 `http://127.0.0.1:4173/`。纯数据、规则、状态与 UI 字符串测试：`node --test tests/*.test.mjs`。

GitHub Pages 的公开地址仍为 [仓库主页](https://aurorasundev.github.io/fitness-audience-agent/)。本分支未合并到 `main` 前，公开地址可能仍显示作业二版本；请以本地预览或功能分支代码为准，不把未发布功能说成已上线。

演示数值：峰值 UV 10,000、11.14 实际 6,000、相似活动参考预期 7,000；下降 4,000 中，预期回落 3,000（75%）、额外缺口 1,000（25%）。渠道缺口只代表结构贡献，不证明广告或其他渠道是原因。产品详情页 UV 没有可用日值，不会继承店铺 UV。截图与数据均为课程演示内容。

作业三的 11-14 付费渠道是实际 800 / 参考 1,300，缺口 500；相对付费渠道预期下降 38.46%，占店铺总额外缺口 50%，两者不能混为一谈或与总缺口相加。11-15/16 是固定 Mock 跟进数据，改善只是观察，不证明某项动作造成恢复。
