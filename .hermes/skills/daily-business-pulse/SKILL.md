# 每日经营巡检

## 目标与边界

面向单店店长，检查已完成自然日的流量、用户、交易与搜索排名，给出今日重点、证据、优先待办和上次问题的后续变化。一次调用只生成一份指定日期的报告；订阅时间、触发和送达由独立任务网关负责。仅使用已授权的只读经营数据，不改预算、价格、报名状态或原始指标。

项目当前的网页原型用固定情景数据和浏览器状态演示此流程。以下是技能的业务执行指令，不代表经营数据适配器、Hermes 定时任务或消息通道已经接入。若运行环境缺少已授权数据工具，停止并说明缺少什么，不用样例数值代替实时结果。

## 输入与前置条件

- **身份与范围：** 调用者身份、授权店铺 ID；仅处理一个获授权店铺。不得从提示词或本地配置推断权限。
- **报告日期：** 北京时间 `Asia/Shanghai` 的一个已完成自然日，统计窗为 `00:00–24:00`；先确认该日数据已就绪。
- **监控维度：** `traffic`、`audience`、`transaction`、`ranking` 的非空子集；只读取被选维度。
- **版本与上下文：** 技能版本、指标口径版本、可比基线、上次报告的持续事项及按业务日期有效的处理反馈。
- **依赖能力：** 分域只读数据查询、指标证据查询、经授权的报告与反馈存储。项目原型中的对应函数是 `queryTraffic`、`queryCustomers`、`queryTransactions`、`queryRanking`、`getEvidence`；这些 JavaScript 函数目前并非 Hermes 已注册的远程工具。

## 执行步骤

1. **核验范围。** 校验店铺授权、日期、维度和版本。无权限、配置无效或报告日期不受支持时停止；返回具体原因与已检查范围。
2. **确认数据就绪。** 逐域检查是否有当日数据及质量状态。缺失域保留为缺失，不能补零、借用别日值或用店铺 UV 冒充商品详情页 UV。
3. **分域取数。** 流量读取店铺 UV、参考预期及互斥主来源渠道；用户读取新访客和回访访客；交易读取支付金额、买家、订单及可用访客分母；排名读取同搜索词、设备、地域和采样时点的快照。不要把四域合成一个自由参数的万能查询。
4. **执行确定性判断。** 店铺 UV 低于参考预期至少 10% 且缺口至少 200 人时列为关注；付费渠道低于参考预期至少 15% 且缺口至少 200 人时优先排查；同条件排名下降至少 5 位只记为待核验线索。用户结构和交易没有可比基线时只展示观察值，不强判异常。
5. **核对证据与不确定性。** 渠道实际值与参考值分别合计到店铺值后，才计算结构贡献。每个异常附指标 ID、口径版本、定义、分子与分母、时间窗、来源、血缘、取数时间和质量状态。渠道缺口占比不等于已证明的成因；不能把付费缺口再加到店铺总缺口上。
6. **输出日报。** 依次给出数据范围与覆盖度、一句话重点、已选维度指标、按优先级排序的异常、每条建议的依据与仍需核查的因素、今日待办、上次问题的后续变化。数据不足时输出部分报告并标出暂停判断的项目。
7. **保存与复用。** 若有获授权存储能力，按店铺、日期、技能版本和配置身份保存报告快照；送达记录另按报告、渠道和日期去重。处理反馈保存 `incidentId`、状态、备注、业务生效日和修订序号。读取历史报告时保留原版本，不按新规则悄悄重算。

## 失败与停止规则

| 情况 | 处理 |
| --- | --- |
| 无授权或缺少可信数据工具 | 停止，列出需要的授权或接口；不得生成完整经营结论。 |
| 单域缺数 | 输出标注覆盖范围的部分日报；依赖该域的指标和建议暂停。 |
| 流量口径冲突或渠道不守恒 | 展示冲突的版本与数值，暂停流量缺口或渠道贡献结论，交由人工核实。 |
| 访客分母缺失 | 可保留支付金额和买家数，暂停买家转化率。 |
| 排名采样条件不可比 | 展示当前快照，取消排名变化告警。 |
| 查询超时或用户中断 | 保留已验证的数据和任务状态，不标为完整成功；提供重试或人工接管所需上下文。 |

## 反馈与规则治理

店长的「已处理」只表示动作已记录；恢复状态必须依据后续经营数据单独判断，差距收窄也不能直接归因于这次处理。「不适用」反馈可在有限时间内抑制相同建议，但新发生的更严重异常仍需检查。

反馈可以形成**报告话术、FAQ 或事项排序**的改进候选。候选必须先做独立样本对照，再经负责人审核、版本发布与回滚；一次反馈不能自动改变指标定义、分母、告警阈值、权限、评测标准或资金动作。订阅创建、暂停和恢复属于任务网关生命周期，不通过这份 `SKILL.md` 自行完成。

正式发布新版本前，产品与数据负责人要确认适用店铺、指标口径和冻结评测样本；历史对照只能作为候选证据，不能替代真实影子运行、灰度和审计。

## 日报输出结构

```text
店铺 · 报告日期 · 数据范围与更新时间 · 覆盖维度/缺失维度
今日重点：一句可被证据支持的判断；不确定处直接说明
经营概况：流量 / 用户 / 交易 / 排名的已取得指标与适用基线
优先事项：变化 → 证据卡 → 尚未核实的因素 → 建议的下一步
今日待办：可记录处理状态与备注，不代替经营系统执行动作
上次问题跟进：前后数据、处理记录、恢复状态分别呈现
```

## 输出检查

交付前逐项核对：报告日期和授权范围清楚；每个异常能追溯到同口径证据；未知值未显示为零；建议动作与证据强度相称；持续问题关联原 `incidentId`；历史处理按业务日期读取；报告生成与提醒送达没有混为一件事。
